## 关键经验教训

### 文档同步模式（每轮标配）
- **每轮结束文档同步**涵盖 6 个文件：README.md（测试数+模块说明）、SKILL.md（测试数+CLI说明+架构演进表）、日报 `500_Journal/Daily/YYYY-MM-DD.md`、changelog `changelog/YYYY-MM-DD.md`、项目主页（迭代日志追加）、workflow run 文件（`~/mem/mem/workflows/runs/`）
- agent-memory 测试增长记录：Phase E→234 → Round 2→247 → Round 3→339 → Round 4→428 → Round 5→491 → Round 6→577
- 每轮 README.md 更新要点：测试数、新模块说明、新 CLI 子命令；SKILL.md 额外更新架构演进表行

### trigger-map 文档维护
- **R3-B weight/efficiency 升级**：主 trigger-map.md 和 11 个 agent trigger-map.md 共 12 个文件统一新增 Weight/效率列；核心链路 1.0，辅助链路 0.8，效率初始 `—`；顶部添加说明段落
- **改进验证链规则**：验证层次分三层（静态验证 / 逻辑审计 / 实战验证），实战验证规则四条，禁止以静态验证替代实战验证声明完成
- **research-first 触发规则**：方案讨论前必须先派 yomi 调研，Weight=1.0

### 设计文档创建
- **设计文档路径规范**：`docs/plans/YYYY-MM-DD-<topic>-design.md`
- **系统架构文档套装**：architecture-diagrams.md（5张Mermaid图）+ system-architecture.md（汇总入口）+ docs/adr/（7个ADR）
- Mermaid 图类型：Agent 拓扑（flowchart）、决策链（flowchart）、Hook 时序（sequenceDiagram）、记忆系统目录（flowchart）、配置加载层级（flowchart）
- ADR 七大核心决策：配置中枢、角色分离、记忆系统、Hook 自动化、SSOT、Subagent-First、Mission Mode

### Obsidian MOC 创建
- MOC 文件命名：下划线开头 `_xxx_moc.md`，统一指向上级 MOC，含标准 Dataview 查询
- Area_区块链 子目录 9 个 MOC 统一指向 `_blockchain_moc`
- 创建后更新父级 MOC 索引引用

### CLAUDE.md 修改（fumio 职责边界）
- **fumio 可以修改 CLAUDE.md**，但 prompt 中禁止含 `rm`/`git commit`/`git push` 等执行命令
- 修改决策链定义（如提升 yomi 至 Phase 0）：Read 文件定位 → Edit 精确替换，保持现有格式一致

### 角色身份保护（CRITICAL）
- fumio 中文名「织者」和职责（管理文档/书籍）不得被修改；曾被错误更改，已记录为 feedback
- 所有 agent 文档编辑产出给人看，不包含系统命令

## 常见任务模式

### 项目主页迭代日志追加
- 固定追加到现有迭代日志区域
- 内容格式：日期 + Round/Phase + 核心变更 + commit hash + 关键设计决策
- 不修改项目主页的状态/目标等其他部分

### hooks README 文档化
- 读取 hook 源码 + settings.json 配置
- 输出内容：触发事件、功能说明、配置参数（含环境变量）、超时设置、故障排除指南
- 路径：`~/.claude/hooks/README.md`

### 日报/changelog 追加
- 日报：追加工作记录到对应日期文件（不覆盖已有内容）
- changelog：追加变更详情（hook 自动生成，fumio 追加手动记录）
