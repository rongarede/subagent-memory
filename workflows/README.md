# Workflows

工作流引擎的数据目录。

## 结构

- `templates/` — 工作流模板（YAML），11 个，定义步骤、依赖、重试规则
- `runs/` — 运行实例（JSON），记录执行状态、结果、断点信息

## 引擎架构

**编排器 / 执行器分离：**

- `root`（编排器）— 调度入口，负责解析模板、路由子代理
- `engine.py`（执行器）— 386 行，零外部依赖，承载全部执行逻辑

### engine.py 函数清单

| 函数 | 职责 |
|------|------|
| `load_workflow` | 读取并解析 YAML 模板 |
| `load_run` | 加载已有运行实例（JSON） |
| `save_run` | 持久化运行状态 |
| `topological_sort` | Kahn 算法分层，返回可并行步骤批次 |
| `get_next_steps` | 检查依赖是否全部 `completed`，返回可执行步骤 |
| `execute_step` | 单步执行，调用子代理或命令 |
| `handle_failure` | 失败决策树（五策略） |
| `resume_run` | 从断点恢复执行 |
| `pause_run` | 暂停并保存断点 |
| `abort_run` | 终止运行实例 |
| `start_run` | 创建新运行实例并启动 |

## 执行流程

**Phase 1 — 初始化**
加载模板 → `topological_sort` 生成分层执行计划 → 创建运行实例

**Phase 2 — 执行循环**
`get_next_steps` 获取就绪步骤 → 并行 `execute_step` → 更新状态 → 循环直至无可执行步骤

**Phase 3 — 终止**
所有步骤 `completed` → 标记运行完成；或 `abort_run` 强制终止

## 失败处理决策树

`handle_failure` 按优先级依次检查：

```
step.on_failure 有设置？
  是 → 执行 step.on_failure 策略
  否 → retry.on_failure 有设置？
         是 → 执行 retry.on_failure 策略
         否 → abort（默认）

策略优先级（高 → 低）：
  retry → goto → pause → skip → abort
```

**on_failure 优先级：** `step.on_failure` > `retry.on_failure` > 默认 `abort`

## 运行状态

| 状态 | 含义 |
|------|------|
| pending | 等待启动 |
| running | 执行中 |
| paused | 暂停（失败等待人工） |
| completed | 全部完成 |
| failed | 重试耗尽 |

## 已知约束

- **skipped 不解锁后续**：`get_next_steps` 只检查依赖是否为 `completed`，被 skip 的步骤不会解锁其下游步骤。设计工作流时需注意避免关键路径上出现可能被 skip 的步骤。

## 反射系统

基于控制论反馈理论的 agent 编排机制，定义在 `trigger-map.md` 中。

### 核心概念

- **原子反射**：最小执行单元，单 agent、单输入/输出、可独立触发
- **转移规则**：反射完成后，根据输出条件决定触发哪个下一反射
- **完成反射**：终结器，任何反射链的收尾步骤（日记 + 记忆并行）

### 转移规则（核心）

| 当前反射 | 输出条件 | → 触发 |
|----------|---------|--------|
| 调研 | 找到问题原因 | → 实现 |
| 调研 | 需要更多信息 | → 探索 |
| 调研 | 需要架构决策 | → root 决策 |
| 探索 | 结构已清晰 | → root 决策 |
| 探索 | 无结果/结构不清 | → 调研 |
| 实现 | 代码变更完成 | → 审计 |
| 审计 | 通过 | → 提交 |
| 审计 | 失败 | → 实现（附失败原因） |
| 提交 | 完成 | → 完成反射 |
| 提交 | 后续仍有实现步骤 | → 实现 |
| 验证 | 通过 | → 提交 |
| 验证 | 失败 | → 实现 |
| 吞食 | 产出约束/skill | → 文档 |
| 文档 | 完成 | → 提交 |
| 定义 | 完成 | → 文档 |

### 类型说明

- **普通**：标准反射，有明确的转移规则
- **枢纽**：提交反射，可触发完成反射或继续实现（分支节点）
- **终端**：日记和记忆，执行完毕后链路结束
